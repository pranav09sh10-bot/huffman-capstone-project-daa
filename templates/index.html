n = number of bytes in the file. k = number of distinct symbols (at most 256 for bytes), so k log k is a small constant and the practical cost is O(n).


    
Why it works

    
Huffman coding is a greedy algorithm: it always merges the two least frequent nodes. This gives an optimal prefix-free code, so the average code length L satisfies H ≤ L < H + 1, where H is the Shannon entropy shown in the statistics.


    
Limits

    
The frequency table is stored in the file (5 bytes per symbol). For very small files this header can make the output larger than the original. Files with uniform random bytes (already compressed or encrypted data) cannot be shrunk.
